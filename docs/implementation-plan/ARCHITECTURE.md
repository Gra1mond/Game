# Направление реализации

## Технология и размещение

Godot 4.7.2 stable Standard, типизированный GDScript, 2D, Compatibility renderer, целевая платформа Windows x64. Точная версия движка и шаблонов — 4.7.2 stable. Linux-бинарник проверен в T01; Windows-бинарник/экспорт пока не проверены. Это отдельный Godot-проект, не перенос HTML.

Будущий проект — `game/` относительно корня репозитория, документация — `docs/implementation-plan/`, сборки — `builds/` с исключением из Git. Это обычная папка проекта, не новый Git-репозиторий.

Плановая структура: `game/core/` (состояние и правила), `game/content/` (описания районов, рецептов, улучшений), `game/world/` (карта и представление машин), `game/ui/` (панели и ввод), `game/persistence/` (файловое хранение), `game/tests/` (проверки публичных интерфейсов). Создавать каталоги по мере появления содержимого.

## Владельцы данных

Один модуль GameSession владеет ProfileState и RunState. Другие модули получают снимок для чтения и передают команды. Виджеты, анимации и движущиеся объекты не меняют кошелёк или прогресс напрямую.

Simulation реализует шаг правил без зависимости от SceneTree, ввода, кадровой частоты и файловой системы. Крупные внутренние части появляются по мере потребности: PortRules, OilRules, QuartzRules и остальные. Глобальный контейнер на каждый район и отдельный универсальный движок рецептов заранее не нужны.

ContentCatalog содержит стабильные ID и параметры. Визуальные пути, имена переводов и численные настройки отделены от прогресса. SaveRepository отвечает за чтение, валидацию, смену формата и безопасную запись. Представление строится из игровых фактов.

## Публичные интерфейсы, предложенные для реализации

Названия ниже — договорённость плана; типы конкретизируются в T01–T02. Изменения фиксируются здесь и в затронутых тикетах.

Конкретизация T02–T03: профиль, snapshot и CommandResult представлены типизированными `Dictionary`; snapshot/export_profile возвращают глубокую копию. Добавлен `is_paused() -> bool` для координатора кадров без копирования всего профиля. `PortRules.advance` двигает действительные фазы работников и возвращает доставленный объём; только GameSession зачисляет его в запас/выпуск. `PortRules.describe` вычисляет цены/темпы/предпросмотр для UI. `world/port_view.gd` читает фазы, интерполирует только положение и не выдаёт ресурсов.

- `GameSession.new_profile(seed)` — чистое новое прохождение, отдельно от престижа.
- `GameSession.dispatch(command) -> CommandResult` — результат с `accepted`, `reason_code`, событиями. Неуспешная команда ничего не списывает.
- `GameSession.advance(step_seconds)` — один шаг симуляции, вызываемый координатором фиксированного времени.
- `GameSession.snapshot() -> GameSnapshot` — доступное для чтения состояние, итоговые скорости, ограничения, прогнозы.
- `GameSession.preview_prestige(allocation) -> PrestigePreview` — вычисление без изменения состояния.
- `GameSession.prepare_prestige(preview_id) -> CandidateProfile` — проверка актуальности и построение полного нового профиля; фиксация через координатор сохранения.
- `SaveRepository.save(profile) -> SaveResult` и `load() -> LoadResult` — один полный профиль за транзакцию, ошибка доступна интерфейсу.

Команды включают ручной сбор, покупку, назначение/возврат рабочего, распределение мощности, направление луча, режим района, исследование, экспедицию к находке и проект. Текущий UI не получает универсальную команду «записать любое поле».

## Порядок шага

Фиксированный шаг 0,1 секунды. Пользовательская пауза останавливает симуляцию; анимация интерфейса может продолжаться. Производство скрытых районов не останавливается. Режим разработки выполняет больше обычных шагов, не умножает уже вычисленные награды задним числом.

Порядок: применить очередь команд → определить доступное топливо и питание → назначить мощность по приоритетам → вычислить эффекты исследований/луча → продвинуть производственные циклы → выдать завершённые результаты и разрешить расходы → обновить пороги и события. Новый выпуск масла доступен для сжигания со следующего шага. Входные материалы резервируются при начале оплаченного цикла. Большой интервал разбивается на шаги; за один вызов нельзя пропустить фазу и получить повторную награду.

При подвисании обработать ограниченное число накопленных шагов и сохранить остаток для следующих кадров; при длительном уходе приложения в фон ставить симуляцию на паузу. Лимит догоняющих шагов и порог фона фиксируются в T02. Время закрытого приложения не догоняется.

## Представление

Карта и UI читают один снимок с идентификатором версии. Числа обновляются по изменению снимка с ограниченной частотой. Машины интерполируют действительные фазы работы; визуальный перелёт не является таймером выплаты.

Состояние станции содержит явное ограничение: `no_worker`, `no_power`, `no_input`, `output_full`, `manual_off`, `working`. Экран переводит код причины и показывает её рядом с действием. Предпросмотр улучшения получает расчёт из правил, не дублирует формулы в кнопке.

Метки времени и диагностика локальны. Генератор случайности, если понадобится, получает сохраняемый seed и состояние. Стартовые находки размещены вручную, случайность не является условием сюжета.
