# Решения, допущения и риски

## Решения текущего плана

| ID | Решение | Причина и следствие |
| --- | --- | --- |
| D01 | Godot 4.7.2 stable Standard + типизированный GDScript, Windows x64 | Зафиксировано и запущено в T01 на Linux/WSL, Compatibility; Windows-проверка пока не выполнена |
| D02 | M1 из трёх районов и полного престижа | Проверяем разнообразие добычи и повторное прохождение до наращивания контента |
| D03 | Шесть ресурсов цикла, эхо между циклами, мощность отдельно | Разные роли без лишних складских счётчиков |
| D04 | Релейная сеть и главный луч — разные функции | Переключение активного внимания не выключает всю экономику |
| D05 | Фиксированный шаг и один владелец игрового состояния | Скорость выплат не зависит от отрисовки и экрана |
| D06 | Один сохраняемый профиль содержит run и meta | Престиж не разрывается на две несовместимые записи |
| D07 | Эхо за ещё не оплаченные рубежи | Сброс продвигает к новым целям, а не награждает за повтор короткого старта |
| D08 | Обычная автоматизация в первом цикле | Повторяющиеся операции постепенно уходят, метадерево даёт новые возможности |
| D09 | Карта задана вручную; находки M1 тоже | Управляемый темп и воспроизводимость обоих маршрутов |
| D10 | Офлайн-доход и Steam-интеграции вне текущего объёма | Полная локальная кампания проверяется раньше внешней публикации |
| D11 | Исходный HTML остаётся справочным экспериментом | Его два ресурса и таймер тумана не определяют новую экономику |
| D12 | Локальное оснащение cargo_hold в T03, исследования за данные остаются T08 | Критерий T03 требует проверить смену выгодного маршрута при большей вместимости; одно оснащение за16 сплава меняет вместимость4→8, не вводя ранние данные и исследования |
| D13 | T04: реле и производство — разные потребители; фронт доступных узлов | Каждый relay требует0.25, станция порта0.75; запросы целиком, приоритет/ID среди доступных из активной цепочки. Приоритет дочернего узла не обходит выключенного родителя |
| D14 | Строительство реле на будущих районах не открывает их добычу | T04 проверяет трёхзвенную сеть без реализации T06/T07/T09. Предварительное port-реле учитывается в цене станции:10+10=20, без скрытого повторного платежа |

Это выбранное направление планирования; оно не выдаётся за отдельно подтверждённый пользователем технический стек. Если выбор движка изменится, перед T01 пересмотреть архитектуру, сохранения, проверки и оценку задач согласованно.

## Главные риски

- **Районы отличаются только скоростью.** Каждому задан отдельный цикл и решение, проверяется при его приёмке.
- **Слишком много ручных переключений.** Базовая работа сохраняется без луча; повторяемые действия автоматизируются.
- **Ранний путь приводит к тупику.** Бесплатное восстановление сплава, возврат работников и два полных маршрута M1.
- **Сброс не даёт нового опыта.** Проверка двух наборов постоянных навыков и достижимых новых рубежей до M2.
- **Ожидание вместо решений.** Анализ доступных альтернатив и обратных усилений в T13/T22.
- **Потеря прогресса.** Полный профиль, кандидаты записи, backup и проверки престижа при сбое.
- **Объём расползается.** Дополнительные механики получают собственные тикеты; M2 ждёт результата M1.

## Как менять решение

Записать дату, наблюдение, новое правило, затронутые требования и тикеты. Пример: если форсаж болота имеет одну всегда лучшую настройку, менять его экономику и критерии T06/T13, а не добавлять ещё один ресурс для маскировки проблемы. Новое требование не считается выполненным только потому, что появилось в документе.
