# План реализации «Маяки в тумане»

Дата: 3 ноября 2026. Ветка: `plan/lighthouse-implementation`. Статус: подготовлен к обсуждению и выполнению; игра по этому плану ещё не реализована.

## С чего читать

1. [IDEA.md](IDEA.md) — полный самостоятельный файл идеи со всеми дополнениями из обсуждения.
2. [SCOPE.md](SCOPE.md) — требования, вехи и границы продукта.
3. [ARCHITECTURE.md](ARCHITECTURE.md) — выбранное направление реализации и интерфейсы модулей.
4. [STATE-AND-SAVE.md](STATE-AND-SAVE.md) — состояние, сохранения, сброс и восстановление.
5. [ECONOMY.md](ECONOMY.md) — правила производства, ограничения и начальные значения для эксперимента.
6. [VERIFICATION.md](VERIFICATION.md) — проверки и предложенные тестовые границы.
7. [DECISIONS.md](DECISIONS.md) — решения, допущения и открытые вопросы.

Тикеты находятся в [tickets](tickets/). Каждый содержит идею, цель, входные условия, границы, детали, критерии приёмки, проверку и конечный результат. Это локальные тикеты; задачи во внешнем трекере не создавались.

## Вехи

**M1 — законченная демонстрация.** Три района с разной добычей, управляемый луч, взаимные усиления, данные и исследования, находки, цель, сохранение, добровольный престиж и повторное прохождение. Ключевая проверка: знакомая часть после сброса короче, а решения меняются.

**M2 — полная кампания.** Ещё три района, дополнительные связи и постоянные технологии, большие проекты, финал, оформление и локальная Windows-сборка. Начинать M2 после оценки M1 и фиксации результатов прохождения.

Последовательность намеренно строится из работающих игровых изменений. Например, T06 включает правила болота, его представление, управление и проверки; отдельного многонедельного этапа «сначала вся экономика, потом весь интерфейс» нет. Прямые зависимости задают безопасный порядок. Параллельная работа возможна после фиксации общих интерфейсов, но сама по себе не является требованием плана.

## Как брать тикет

Перед началом прочитать IDEA, связанные правила и предыдущий тикет. Убедиться, что входные условия выполнены. Уточнить только решения, от которых зависит корректность текущей задачи; изменения дизайна записывать в DECISIONS и затронутые тикеты.

Каждый тикет заканчивается работающим результатом, проверкой критериев приёмки, короткой записью о проверках и отдельным коммитом. В будущем рабочие ветки удобно называть `feat/T03-port`, `feat/T11-prestige`; база — завершённые зависимости. Номера тикетов стабильны.

Размер задачи ограничивается её наблюдаемым результатом. Если при реализации появляется самостоятельная крупная механика, выделить новый тикет с зависимостью, не добавлять её скрыто в текущий.

## Общая готовность результата

- Реализованы критерии конкретного тикета, границы соблюдены.
- Данные изменяются через правила игры, интерфейс отражает результат этих правил.
- Обычный путь, отсутствие ресурсов и выход/повторный вход проверены там, где применимо.
- Пройдены подходящие проверки из VERIFICATION; ошибки и ограничения записаны.
- Все новые сохраняемые поля имеют значения по умолчанию и правило загрузки.
- Есть инструкция воспроизведения результата и коммит с ID тикета.

## Что уже существует

Источником требований для нового плана является IDEA в этой папке. HTML — справочный эксперимент; его экономика и код не становятся автоматически реализацией нового проекта.

Движок, проект, тестовый раннер и Windows-сборка ещё не созданы. Команды в документах описывают будущие результаты соответствующих тикетов.
