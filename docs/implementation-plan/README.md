T01–T04 и спецификация PR #3 подтверждены/приняты в `dev`. T05 реализован и проверен в `feat/T05-beam`: главный луч, эффект порта, управление. Следующая остановка — подтверждение PR T05 перед T06. Команды/доказательства — в корневом README и [codex.md](../../codex.md).

7. [DECISIONS.md](DECISIONS.md) — решения, допущения и открытые вопросы.
8. [REVIEW.md](REVIEW.md) — результаты независимой проверки плана и исправленные замечания.

REVIEW сохраняет историческую независимую проверку исходного плана, не выдаётся за ревью новых требований. Новые решения подтверждены пользователем через grill-me и отражены в DECISIONS; факт появления документа не означает выполненную механику.

Тикеты находятся в [tickets](tickets/). Каждый содержит идею, цель, входные условия, границы, детали, критерии приёмки, проверку и конечный результат. Это локальные тикеты; задачи во внешнем трекере не создавались.

## Вехи

**M1 — законченная демонстрация.** Три района, управляемый луч, взаимные усиления, исследования, находки, цель, сохранение и полный повторный цикл. T12A добавляет ранний художественный срез корабля/сборщика/порта и 3D-инспектор до приёмки T13, но не героев/экипаж. Проверяем ускорение знакомого старта и изменение решений.

**M2 — полная кампания.** Ещё три района, проекты/финал, люди и найм T17A, личное развитие T17B, общее дерево 36 узлов/автоматизация T18, полный графический набор и Windows-сборка. Начинать после оценки M1; нужные ассеты появляются вместе с механикой, T20 завершает покрытие, а не заменяет предыдущие рабочие срезы.

## Как брать тикет

Перед началом прочитать IDEA, связанные правила и предыдущий тикет. Проверить входные условия и разрешение продолжать после предыдущего PR. При реализации использовать установленный `/tdd`: один публично наблюдаемый пример → падающая проверка → минимальная реализация → следующий пример. Вопросы, разрешимые кодом/документами, исследовать самостоятельно; существенные новые решения согласовывать и фиксировать в DECISIONS.

Каждый тикет заканчивается работающим результатом, проверкой критериев приёмки, короткой записью о проверках, отдельным коммитом, push и PR в `dev`. После ссылки и результатов запросить подтверждение пользователя и ждать; без ответа следующий тикет не начинать, PR самостоятельно не сливать. Рабочие ветки: `feat/T03-port`, `feat/T11-prestige`; база — завершённые зависимости. Номера тикетов стабильны.

Перед автопродлением/сбросом при исчерпании лимита сначала спросить разрешение пользователя. Не обещать недоступное управление лимитами платформы; checkpoint в [codex.md](../../codex.md) обновлять перед остановкой и после проверки/PR. Не обходить ожидание подтверждения новой веткой или следующим тикетом.

Размер задачи ограничивается её наблюдаемым результатом. Если при реализации появляется самостоятельная крупная механика, выделить новый тикет с зависимостью, не добавлять её скрыто в текущий.

## Общая готовность результата

- Реализованы критерии конкретного тикета, границы соблюдены.
- Данные изменяются через правила игры, интерфейс отражает результат этих правил.
- Обычный путь, отсутствие ресурсов и выход/повторный вход проверены там, где применимо.
- Пройдены подходящие проверки из VERIFICATION; ошибки и ограничения записаны.
- Все новые сохраняемые поля имеют значения по умолчанию и правило загрузки.
- Есть инструкция воспроизведения результата и коммит с ID тикета.
