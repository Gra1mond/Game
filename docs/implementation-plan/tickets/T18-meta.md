# T18 — Глобальные таланты и технологии полной кампании

Статус: запланирован. Веха: M2. Спецификация, не выполненная реализация.

## Основная идея

Поздние циклы меняют способы управления, сохраняя интерес ранних районов. Глобальная сборка не является личным деревом героя.

## Цель

Заменить небольшое дерево M1 законченным глобальным деревом из 36 узлов, сохранять два полных бюджета при новом выборе и дать реальные поздние способы управления без обязательной редкости или бесплатной экономики.

## Входные условия

Завершён [T17B](T17B-hero-development.md); он включает T17A/T17/T12A и действующие базовые шансы/личные деревья. T19 не является зависимостью: финальная нормальная цель подключается к событию T19 при его реализации.

Прочитать [IDEA](../IDEA.md), [SCOPE](../SCOPE.md), [архитектуру](../ARCHITECTURE.md), [состояние](../STATE-AND-SAVE.md), [экономику](../ECONOMY.md), [CREW-AND-TALENTS](../CREW-AND-TALENTS.md), [ART-AND-ASSETS](../ART-AND-ASSETS.md) и [проверки](../VERIFICATION.md). При противоречии сначала актуализировать общий договор в [DECISIONS](../DECISIONS.md).

## Входит в тикет

- 36 действующих глобальных узлов: шесть ветвей `log/eng/prod/start/hire/control`, каждая с тремя нормальными и тремя престижными узлами; точный начальный каталог/цены/родители/владельцы эффектов — CREW-AND-TALENTS. Узлы не пустые подписи и не второй личный геройский экран.
- Нормальные глобальные очки за новые уникальные profile-scoped цели и престижные покупки за **существующее эхо**. TOTAL каждого бюджета включает вложенное, реестры оплаты исключают повтор.
- Полный возврат обоих глобальных бюджетов с обнулением всех allocations при престиже; новый набор выбирается перед созданием RunState. Доступные по числу престижей ярусы сохраняют доступность, но проходные узлы/эффекты покупаются заново за возвращённый бюджет.
- Реальные выбранные модификаторы вероятностей ветеранства/врождённого/редкого пассива, не автоматическая прибавка за prestige count.
- Одноразовые стартовые ресурсы/кредиты, явный полный сброс лодок/людей/личного развития/остатка кредитов, без возврата личных очков.
- Пороги M2, интеграция разветвлённой оптики/трасс, сохранённые планы восстановления станций, расписание главного луча с ручным override и ограниченная портовая работа вне **световой сети**.
- Конечная versioned миграция полного профиля M1/T17A/T17B на новое дерево, отчёт и информированный однократный выбор без принудительного дополнительного престижа.

## За границами тикета

Бесконечный фарм эхо/кредитов/нормальных очков, обязательная единственная сборка, сюжетные ключи/невозвратные платы за ветви, автономный бот прохождения всей игры, геройские престижные покупки/вечный личный банк, реальные платежи. Обычные исследования за данные не превращаются в глобальные нормальные очки. Районы не открываются фиксированным количеством престижей.

## Необходимые детали реализации

1. Начать с поведенческих тестов и каталога из CREW-AND-TALENTS: 18 нормальных и 18 престижных узлов, по одному уровню; цены в ветви 1/2/3 соответствующего бюджета. N1→N2→N3 и P1→P2→P3 — две цепи; доступ N1 с начала, N2/P1 после первого престижа, N3/P2 после второго, P3 после третьего. Узел-проход имеет реальный эффект, полностью возвращаемую цену и не требует отдельного сюжетного ключа. Покупка атомарно проверяет родителей/доступ/оба независимых бюджета; бесплатный доступ к ярусу не равен купленному эффекту.
2. `total_normal_points`/`claimed_normal_goal_ids` отдельно от `total_echo`/старых milestone IDs; global_allocation.normal/.prestige не смешиваются. Уникальная нормальная цель оплачивается по событию один раз на профиль, не при каждом сбросе. Подключить реальные достижимые до T19 цели начального реестра; контент будущего Сердца света не симулировать фиктивным событием.
3. При престиже сначала один раз зачесть законные новые награды, затем сохранить оба TOTAL, очистить allocations и предложить новый набор. Не вычислять refund как `total + spent`: total уже включает spent. Пример: нормальных total10/spent7 остаётся 10, эхо total8/spent6 + новый milestone2 становится 10; личные 4 очка капитана исчезают. Отмена/ошибка записи оставляют целый прежний профиль, повтор commit/load не повторяет награду/возврат. Новый доступный tier определяется сохранённым cycle_index, не новым кошельком ключей.
4. Личные уровни/XP/очки/узлы, качества и все люди/лодки текущего цикла удаляются вместе с RunState, остаток recruit_credits тоже. Их цена/XP не попадают ни в один глобальный total. Новый цикл даёт одну базовую лодку/одного обычного моряка; гарантированные нормальные роли вновь доступны обычным прогрессом, без рандомного замка кампании.
5. Только подтверждённый новый набор определяет начальные ресурсы/кредиты до создания нового run_id. Выдать их один раз с маркером старта; preview/respec/load/retry не выдают заново. Не выдавать стартом эхо/нормальные глобальные очки, не считать старт/возврат расхода производственным выпуском. Экран показывает отдельные бюджеты, потери людей и точный новый старт.
6. Шансы T17B сначала действуют без модификаторов. Узлы `hire` прибавляют только выбранные п.п. к соответствующим таблицам с нормировкой/пределами и точным предпросмотром совместных вероятностей. При всех начальных узлах подготовка 73/24/3%, врождённое33%, редкое5%; без них остаётся 80/18/2%,25%,3% даже после многих престижей. Не менять уже созданного героя и не обещать гарантированный редкий результат.
7. Применять эффекты через существующие ограниченные группы: глобальные/личные/ролевые/innate/rare складываются внутри постоянной группы по параметру, а не перемножаются по источнику. Пределы и условия из мастер-спецификации обязательны; груз/мощность/масло не создаются сменой сборки. Каждый из 36 узлов имеет проверенный реальный эффект; неподходящая лодка объясняет условие без скрытого бонуса.
8. План восстановления выполняет обычные покупки через команды, соблюдая открытые районы/цены/питание/людей; нехватка средств объясняется и не списывается повторно. План/расписание сохраняются как предпочтения между циклами, но исполняются только с заново купленной технологией. Ручной выбор луча действует до явного «возобновить расписание» и не отменяется следующим tick. Интегрировать существующие разветвлённые трассы/оптику T17 без бесплатной мощности или второго главного луча.
9. Ограниченная работа вне световой сети — портовый выезд от связанной базы к уже доступной цели, только с реальным человеком и заранее оплаченным конечным маслом; 25% базовой погрузки, cap50%, защищённый запас возврата, максимум60с внешней работы. Точные стартовые числа/фазы/резерв описаны в CREW-AND-TALENTS и являются гипотезами. Исчерпание/потеря связи базы безопасно возвращают лодку; незавершённая погрузка не создаёт груз, загруженный доставляется один раз; остаток топлива возвращается один раз и не считается выпуском. Не питать отключённые станции, не открывать новый район, не заменить требование световой сети простым отсутствием бонуса главного луча (это уже допустимо без узла).
10. До cutover M1-дерево T11 полностью действует. Миграция сохраняет полный total_echo, удаляет старый allocation без повторного прибавления spent, восстанавливает нормальные награды только по доказанным сохранённым целям и сразу записывает claimed IDs. Сохраняет текущие wallet/людей/XP/RNG/кредиты/фазы/трюм/прогресс; сама не является престижем. Сначала пауза/отчёт и однократный подтверждённый выбор нового набора из возвращённых бюджетов; не заставлять ещё раз престижиться. Стартовые подарки, ранее полученные/потраченные в M1, не отзывать и не переиздавать; новые стартовые узлы ждут следующего настоящего RunState. Нулевой набор — staging выбора, не незаметный лишённый эффектов текущий цикл. Закрытие/ошибка save сохраняют целый профиль/ожидание выбора; после успешной конверсии нет постоянно работающего старого дерева, alias/re-export/shim или второго кошелька эхо.
11. Обновить пользовательские правила, схемы/миграционные фикстуры, каталог/независимые примеры и запись проверки по наблюдаемому результату. Числа — начальные гипотезы, не итоговая балансировка T22.

## Критерии приёмки

- [ ] Ровно 36 глобальных узлов с реальными эффектами/ценами/родителями и хотя бы двумя рабочими различающимися наборами; сюжет не требует одного узла или редкого героя.
- [ ] Обе суммы бюджета сохранены, включая вложенное; при сбросе allocations нулевые до нового выбора, возврат однократный, личные бюджеты удалены без компенсации. Пример 10 нормальных /10 эхо воспроизводится.
- [ ] Ярус становится покупаемым после престижа, доступ остаётся, эффекты/проходы нужно оплатить вновь; нет невозвратного ключевого расхода. Районы по-прежнему открываются текущим производством/проектами.
- [ ] Стартовые ресурсы/кредиты выдаются ровно один раз после подтверждения нового набора; ни повтор команды/load/respec, ни выдача старта не создают эхо/новые глобальные награды/бесплатный груз.
- [ ] Выбранные узлы изменяют реальные таблицы найма, без автоматического скейлинга престижем; без узлов базовые шансы неизменны, редкость не обязательна.
- [ ] План сокращает рутину/объясняет нехватку, повтор не строит лишних станций/работников; расписание соблюдает manual override и доступность технологии после reset/load.
- [ ] Реальный ограниченный выезд вне световой сети расходует конечное масло и корректно возвращается при исчерпании/разрыве; не клонирует груз/топливо и не питает отключённый район.
- [ ] M1/T17A/T17B мигрируют целиком с однократным информированным выбором нового дерева, без дополнительного престижа, потери текущей работы/людей или повторных стартовых наград; старый runtime-путь удалён.

## Проверка

Матрица каждого узла/условия/cap и покупки при недостатке/неправильном родителе/tier; новые/повторные цели; бюджеты до/после престижа, ошибка/retry/load и стартовые маркеры; детерминированные шансы с/без `hire` при разных cycle_index; повтор плана/отказ покупки/override; тёмный рейс с окончанием/исчерпанием/грузом/разрывом/save. Миграционные фикстуры M1, T17A/T17B, уже M2 и отказ записи. Ручное сравнение минимум двух сборок ранней/поздней экономики и нового слабого экипажа после сброса.

Игровые тесты писать только через согласованные интерфейсы. В записи результата указать выполненные проверки, наблюдаемый итог и оставшиеся ограничения.

## Финальный результат

Полное глобальное межцикловое развитие, безопасный новый выбор и ограниченная управляемая поздняя автоматизация, не смешанная с личными XP героев.

Коммит содержит ID T18, изменения и короткую запись проверки. После TDD, запуска и приёмки — commit/push/отдельный PR в dev; STOP и запрос подтверждения пользователя перед следующим тикетом. Следующий тикет начинает работу с этого наблюдаемого результата.
