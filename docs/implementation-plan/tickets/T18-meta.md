# T18 — Постоянные технологии полной кампании

Статус: запланирован. Веха: M2.

## Основная идея

Поздние циклы меняют способы управления, сохраняя интерес ранних районов.

## Цель

Расширенное метадерево даёт разные рабочие специализации и сокращает повторную настройку.

## Входные условия

Завершены: [T17](T17-projects.md).

Прочитать [IDEA](../IDEA.md), [SCOPE](../SCOPE.md), [архитектуру](../ARCHITECTURE.md), [состояние](../STATE-AND-SAVE.md), [экономику](../ECONOMY.md) и [проверки](../VERIFICATION.md). При противоречии сначала актуализировать общий договор в [DECISIONS](../DECISIONS.md).

## Входит в тикет

- Пороги M2, разветвлённая оптика, ограниченная работа сборщиков вне света.
- Сохранённые планы восстановления станций и расписание луча как поздние технологии.

## За границами тикета

Бесконечный фарм эхо, обязательная единственная сборка навыков, автономный бот прохождения всей игры.

## Необходимые детали реализации

- План выполняет обычные покупки через команды, соблюдает доступность/цены/питание; отсутствие средств не расходует повторно.
- Настройки сохраняются между циклами, но применяются только при доступной технологии. Автоматический луч подчиняется ручному override по явному правилу.
- Эхо остаётся одним бюджетом; сохранить совместимость allocation M1 и обработку удалённого/изменённого перка.

## Критерии приёмки

- [ ] Два разных набора проходят раннюю и позднюю части без обязательного одинакового перка.
- [ ] План восстановления сокращает рутину и объясняет ожидание недостающих ресурсов.
- [ ] Смена цикла, загрузка и перераспределение не создают бесплатных построек/рабочих.

## Проверка

Повторное выполнение плана, отказ покупки, включение расписания и ручной override; интеграция с престижем/старым save.

Игровые тесты писать только через согласованные интерфейсы. В записи результата указать выполненные проверки, наблюдаемый итог и оставшиеся ограничения.

## Финальный результат

Полное межцикловое развитие и ограниченная управляемая автоматизация.

Коммит содержит ID T18, изменения и короткую запись проверки. Следующий тикет начинает работу с этого наблюдаемого результата.
