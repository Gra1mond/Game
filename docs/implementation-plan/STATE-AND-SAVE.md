# Состояние, сохранение и престиж

## Минимальная модель

| Область | Основные поля | Жизненный цикл |
| --- | --- | --- |
| SaveEnvelope | schema_version, content_version, revision, profile_id | Файл целиком |
| ProfileState | total_echo, allocation, claimed_milestone_ids, discovered_locations, story_flags, cycle_index | Между экспедициями |
| RunState | run_id, seed, tick, wallet, lifetime_produced, stations, relays, workers, upgrades, goals, finds, project_stages, beam_target, oil_boost_target, oil_boost_enabled | Текущий цикл |
| StationState | id, built, enabled, assigned_workers, power_request, priority, mode, phase, phase_progress, pending_output | Текущий цикл |
| WorkerState | id, assignment, target, phase, phase_progress, cargo, recall_pending, queued_assignment, queued_target; expedition_target по мере появления находок | Текущий цикл |
| Settings | volume, text_scale, effects, input_settings, automation_preferences | Отдельно от игрового профиля |

`lifetime_produced` означает суммарный выпуск внутри текущего RunState, не за все экспедиции. Расход не уменьшает его. Между экспедициями сравнение идёт по `claimed_milestone_ids`, принадлежащему профилю. Факт увиденной локации не равен построенной и питаемой станции.

Расчётные скорости, соединения и ограничения пересчитываются после загрузки, не являются вторым источником истины. Сохраняются незавершённые циклы, нагруженные маршруты, очередь сигналов, доля посева и заряд колодца по мере появления соответствующих районов.

Работник создаётся `RunState.create_worker`: idle, пустое назначение/очередь, target/queued_target=near, phase_progress=0, cargo=0, recall_pending=false. В новом цикле есть w1. Станция port присутствует в stations только после покупки; поля id/kind/region=port/enabled=true/power_request=0.75/priority=0. Оснащение upgrades.cargo_hold: отсутствует=0, приобретено=1. В T10 загрузить эти поля вместе с очередью возврата; пропущенные необязательные поля получают defaults, некорректные значения не маскируются ими.

T04: `run.relays` по умолчанию `{}`, ключи port/oil/quartz/coastal; записи built=true,enabled=true,power_request=0.25,priority=10. Отдельное выключение станции не выключает реле. ID потребителя в командах: station ID либо `relay:<region>`. `meta.discovered_locations` хранит известные острова и не уменьшается при разрыве. Выбранный остров и трансформации карты — только UI, не состояние производства.

`GameSession._network` — пересчитываемый кэш, НЕ поле профиля и НЕ сохраняется. Содержит регионы, фактические связи и выделенную мощность; после будущей загрузки пересчитать из relays/stations/discovered_locations. Пока формат сохранения не выпущен (T10), миграция файлов не объявляется выполненной.

### Планируемое расширение M2

Следующая таблица — требования будущих T17A/T17B/T18, не поля уже выпущенного сохранения. Канонические имена/каталог и переходы описаны в [CREW-AND-TALENTS](CREW-AND-TALENTS.md); один смысл не хранится под несколькими независимыми счётчиками.

| Область | Новые факты | Жизненный цикл |
| --- | --- | --- |
| ProfileState | `total_normal_points`/`claimed_normal_goal_ids`, существующий `total_echo`/`claimed_milestone_ids`, `global_allocation.normal/.prestige`; доступ вычисляется из сохраняемого cycle_index | Бюджеты/цели/доступность сохраняются, раскладка выбирается заново |
| RunState | `recruit_credits`, `crew_people`, `active_role_assignments`, предложения/контракты/результаты, recruitment RNG, run_id/маркер стартовой выдачи | Новый цикл создаёт новые записи; прежние не переносятся |
| Личность экипажа | Стабильный ID экземпляра, тип/роль, назначение, вариант внешности | Один человек — одна лодка; обычный матрос без геройского дерева |
| HeroState | ID/role, `xp_total`, `learned_node_ids`, `generated_traits`, внешний вариант; уровень/свободные личные очки вычисляются, не хранятся вторым кошельком | Только этот герой текущей экспедиции; без престижных покупок/возврата |
| Settings | Остановка вращения/сниженные эффекты инспектора | Вне игрового профиля; применение не создаёт наград |

Работник W1/W2 из M1 — техника, не матрос внутри неё. При переходе к обязательному экипажу T17A детерминированно создаёт необходимого моряка каждой старой лодки, сохраняя фазу/трюм/очередь. Само преобразование лодок не выдаёт кредиты, эхо или второй стартовый запас; новые награды найма за уже доказанные события отдельно зачисляются один раз с claimed ID по CREW-AND-TALENTS. Все личности/ссылки фиксируются в мигрированном профиле, повторная загрузка не повторяет конверсию/награду.

Исчезнувшие личные очки не пополняют общие бюджеты. Генератор ветерана создаёт согласованный уровень, очки/выученные узлы и признаки экземпляра; сохранение содержит результат, а не одну лишь вероятность для нового броска при загрузке. Уже раскрытый герой/предложение не пересоздаётся по текущей таблице шансов. Состояние Viewport, угол поворота и ресурсы мешей в профиль не входят.

## Инварианты

- Запасы, количество рабочих, доля цикла и расходы не отрицательны; числа конечны.
- Один рабочий имеет не более одного назначения. Рабочий в экспедиции не работает в порту.
- Цена, условия и наличие рабочего проверяются одной командой до списания.
- Завершение производственного цикла выдаёт результат один раз.
- В M1 стоимость allocation не превышает total_echo. В M2 отдельно проверяются полный обычный общий бюджет и полный бюджет эхо; свободный остаток равен бюджету минус цена выбранных уровней, не ещё одному пополняемому «возврату».
- Престиж не выдаёт повторно награду за уже оплаченный milestone ID.
- Ошибка сохранения не выдаёт игроку частично сброшенный профиль.
- Снимок для отображения нельзя использовать для прямого изменения кошелька.
- Человек назначен не более чем в одну лодку, герой занимает не более одного из мест капитана/инженера/штурмана; один экземпляр не даёт два бонуса. Пустая лодка M2 не начинает производственную работу.
- Цена найма, роль, наличие предложения и создание личности проверяются/фиксируются вместе; повторное подтверждение, ошибка записи или загрузка не дают бесплатного героя/переброс.
- Обычные общие цели оплачиваются единожды по профилю; личный XP начисляется только за работу конкретного экземпляра, не за меню/переназначение/загрузку.
- Стартовый запас применяется один раз к новому run_id после выбранной раскладки, никогда к загрузке существующего RunState. Эти таланты не создают эхо/престижные очки.

## Автосохранение и загрузка

Плановый период — 30 секунд активной игры, плюс важные покупки/проекты с объединением близких запросов, выход через меню и завершённый престиж. Запись сериализована: одна запись за раз, более новая revision не заменяется устаревшей. Профиль целиком сохраняется в один логический снимок.

В `user://` использовать основной файл, временный файл и последнюю исправную резервную копию. Новая запись сначала полностью формируется и проверяется, затем сохраняется во временный файл и закрывается. Последняя исправная версия остаётся доступной до успешного продвижения новой. Конкретные операции переименования проверяются на Windows в T10; не считать перезапись двух файлов одной атомарной операцией.

Commit point — успешно продвинутый и проверенный основной файл новой revision. До этой точки save возвращает ошибку и новая revision не считается зафиксированной. Временный файл никогда не является кандидатом автоматического восстановления, даже если он полностью записан: он может принадлежать операции, которую игрок уже видел как неудачную. После commit point ошибка удаления временного файла или обслуживания backup не отменяет успех сохранения; при спорном результате продвижения проверить основной файл и вернуть статус согласно фактически зафиксированной revision.

При загрузке сначала проверить версию основного файла. Если он содержит неподдерживаемую будущую версию, остановить обычную загрузку и автосохранение; не подменять его старым backup. Показать сообщение о необходимой версии игры. Новый профиль возможен только отдельно, не поверх этого файла.

Для поддерживаемой версии проверить формат, конечность чисел и ссылки на content ID. Выбрать новейший целый допустимый снимок из основного и резервного; временный файл игнорируется независимо от полноты. При восстановлении показать понятное сообщение. До успешной загрузки обычное автосохранение запрещено. Неподдерживаемая версия в резервной копии тоже не даёт разрешения перезаписать её при восстановлении; такие файлы сохраняются отдельно от рабочего набора до явного решения пользователя.

Начальный формат v1 вводится в T10. Новые поля с прежним смыслом получают явные defaults и фикстуры старого формата. Изменение смысла требует версии и миграции; точные номера фиксируются по фактически введённым форматам, не объявляются реализованными заранее. T17A владеет конверсией M1 в экипажную модель, T17B — развитием/контрактами героев, T18 — заменой малого метадерева общим. T23 проверяет всю цепочку, а не впервые чинит её. Часы компьютера не дают офлайн-доход.

## Престиж как одна операция

1. Предпросмотр без мутации проверяет revision, новые milestone IDs/награду, потери, доступные бюджеты и выбранную раскладку. В M2 прежние общие вложения целиком доступны для нового выбора; старую раскладку не переносить автоматически, личные очки героев не возвращать.
2. Подтверждение создаёт целый кандидат: добавляет только новую награду эхо, отмечает рубежи, увеличивает cycle_index/доступность ярусов и строит новый RunState по подтверждённой раскладке. M2 сохраняет полные общие бюджеты, один раз применяет разрешённый стартовый запас/экипаж/кредиты и не копирует старых героев/XP. Стоимость проходных узлов входит в обычную цену раскладки, а не в необратимый ключ ветви.
3. На время операции остановить команды игры. Сохранить кандидат через SaveRepository. При успехе заменить активный профиль кандидатом, затем показать новый берег. При ошибке оставить прежний профиль и предложить повторить запись.
4. Повторный клик и восстановление после сбоя не повторяют награду: новый профиль уже содержит run_id и список оплаченных рубежей. После сбоя загрузка выбирает либо целый старый, либо целый новый профиль.

Престиж доброволен после Берегового маяка и требует нового оплачиваемого рубежа. В M1 действует малое дерево T11. В M2 бюджет и доступность ярусов сохраняются, уровни выбираются заново; стартовые эффекты применяются только при создании кандидата. География, история и предпочтения автоматизации остаются, но предпочтение не заменяет покупку нужной технологии текущей раскладки. Счётчик сбросов открывает ярусы, не повышает сам по себе качество найма.

## Граничные случаи для тикетов

Выход с грузом; граница выплаты; нулевое масло; отключение реле; смена луча вне экрана; повтор покупки/найма; два сохранения; заполненный диск; сбой престижа; миграция M1 с работающими лодками; загрузка с назначенными людьми/личным XP/раскрытым контрактом; возврат обоих общих бюджетов без возврата геройских очков; повторный стартовый бонус; неизвестный content ID. Детальные миграционные фикстуры принадлежат первому тикету, меняющему контракт.

Ожидаемое поведение уточняется в тикете, владеющем соответствующей механикой. Общие решения меняются здесь, а не копируются несовместимыми версиями в разных задачах.
